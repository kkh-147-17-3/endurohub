# 닷 인디케이터 사용 규칙

- 제목, 설명문, 메뉴, 카드, 일반 목록 앞에 장식용 점을 붙이지 않는다.
- 목록의 구분과 시각적 리듬은 여백, 정렬, 타이포그래피로 해결한다.
- 점은 상태 또는 카테고리를 빠르게 구분해야 할 때만 허용한다.
- 텍스트, 배경색, 테두리 등으로 이미 같은 의미를 전달한다면 점을 추가하지 않는다.
- 한 종목이나 동일한 상태만 표시되는 화면에서는 반복되는 점을 생략한다.
- 카테고리용 색상과 상태용 색상을 혼용하지 않는다.
- 점을 없앤 자리를 불필요한 아이콘이나 배지로 대체하지 않는다.
- 의미 있는 색상 정보에는 텍스트 등 색 이외의 식별 수단도 제공한다.

구현 전에 점이 들어가는 각 위치에서 “이 점을 제거하면 어떤 정보가 사라지는가?”를 검토한다. 명확한 답이 없으면 제거한다.

# 정보 위계와 가운뎃점 사용 규칙

- 장식보다 정보 위계를 먼저 설계한다. 각 텍스트를 제목, 설명, 메타정보, 상태, 조작 요소로 구분한다.
- 서로 역할이 다른 정보를 가운뎃점으로 한 줄에 나열하지 않는다.
- 제목이나 필터에서 이미 알 수 있는 정보는 반복하지 않는다.
- 짧고 동등한 메타정보를 묶을 때만 가운뎃점을 사용한다.
- 가운뎃점을 없앤 자리를 다른 구분자, 아이콘, 배지로 자동 대체하지 않는다.
- 불필요한 정보는 삭제하고, 필요한 정보는 여백·정렬·위치로 구분한다.
- 사용자의 주요 과업에 도움이 되지 않는 라벨은 추가하지 않는다.
