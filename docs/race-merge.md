# 중복 대회 병합

중복 후보는 운영자가 확인하고 남길 대회 ID를 직접 지정합니다. 제목 유사도만으로 자동 병합하지 않습니다. 이 문서의 ID는 예시이며 실제 DB에 자동 실행되지 않습니다.

```powershell
cd api
# 반드시 신규 모델/제약조건 마이그레이션부터 적용한 환경에서 실행
python manage.py migrate
python manage.py merge_races --source 250 --target 117
# 위 미리보기의 제목·이전 URL·관계 건수·필드 차이를 검토한 후에만 실행
python manage.py merge_races --source 250 --target 117 --apply
```

`--apply`가 없으면 조회만 합니다. 대회일, 대회종료일, 종목이 다르면 중단합니다. 서로 다른 회차를 강제로 합치는 옵션은 제공하지 않습니다. 원본 DB 백업은 별도로 유지하고, 운영 중 일반적인 마이그레이션 절차를 따르세요.

병합은 단일 트랜잭션이며 두 대회와 연결 행을 잠급니다. 날짜·종목·URL 소유권·새로운 미지원 관계·참가 계획 메모 길이 충돌을 검증하고, 오류 시 전체를 롤백합니다. 동시 실행으로 이미 병합된 ID가 들어오면 중단합니다. 기존 단말/작업이 원본 ID를 쓰는 요청은 삭제된 원본에 새 데이터를 만들 수 없으므로 실패 시 정규 URL로 재시도해야 합니다.

대회 정보는 선택한 target을 유지합니다. source의 정보로 빈 값이나 가격·종목을 임의 보충하지 않습니다. 조회 수만 합산합니다. 두 대회와 모든 직접 연결 행의 병합 전 스냅샷은 `race_merge_logs`에 저장하며 target이 나중에 다시 병합돼도 원래 ID를 유지합니다. 이 로그는 자동 복원 명령이 아니며, 운영자가 복구할 때 참고할 감사 자료입니다. 로그에는 회원 데이터가 포함되므로 기존 운영 DB와 같은 접근 통제를 적용합니다.

리뷰는 작성자·내용·ID·공감과 작성 시각을 그대로 보존해 target에 연결합니다. 같은 회원이 양쪽에 작성한 리뷰도 지우지 않습니다. 가져온 리뷰에는 `merge_source_race_id`로 출처를 남깁니다. 이후 일반 리뷰 작성은 기존처럼 회원당 대회 1회를 검사합니다. 완주 기록도 모두 target에 연결합니다. 같은 회원의 현재 기록이 이미 target에 있으면 source 기록을 병합 이력으로 남기며, 일반 기록 수정·시즌 화면은 단일 현재 기록만 사용합니다. 이력 기록은 내 기록 목록과 공개 설정에 따른 상세 기록 목록에 유지됩니다. 대회별 기록 삭제는 현재 기록만 삭제하며, 이력은 회원의 개별 기록 삭제로 제거할 수 있습니다.

관심 대회는 모든 회원을 유지하고 양쪽에 있는 같은 회원의 관심만 1개로 합칩니다. 관심 등록일은 더 이른 날짜를 유지합니다. 참가 계획은 참가 예정 상태를 우선하고 종목 코드 합집합·목표 여부 OR·서로 다른 두 메모를 보존합니다. 합친 메모가 200자를 넘으면 양쪽 메모를 변경하지 않고 병합을 중단합니다. 게시글의 대회 연결은 합집합으로 유지하고 대기 변경내역은 모두 옮깁니다. 리뷰 ID가 유지되므로 공감 및 리뷰를 참조하는 데이터도 그대로 유지됩니다. 현재 rewards 앱은 대회 FK가 없고 리뷰/완주기록을 조회하므로 기존 참여 자료가 보존됩니다.

source의 슬러그와 숫자 ID URL은 `race_aliases`로 target을 가리킵니다. A→B 다음 B→C 병합은 기존 별칭도 C로 옮겨 체인을 없앱니다. 웹 상세의 기존 정규 슬러그 리다이렉트가 최종 URL로 301 응답합니다. 새 대회 자동 슬러그는 과거 별칭을 재사용하지 않습니다. 내장 마라톤 크롤러는 별칭에 저장한 원본 source URL/external ID를 확인해 이미 합친 원본을 재생성하지 않습니다. 별도 외부 수집기가 DB에 직접 쓰는 경우에도 동일한 별칭 확인을 적용해야 합니다.

분석 이벤트의 `item_type=race`인 source `item_id`는 target ID로 정규화합니다. 원래 이벤트 본문(properties)은 변경하지 않으며 병합 전 이벤트 스냅샷으로 원래 식별자를 확인할 수 있습니다. 병합 성공 커밋 뒤 캐시를 비워 기존 추천/목록 캐시가 삭제된 대회를 가리키지 않게 합니다. 커밋 후 캐시 연결이 실패하면 병합은 이미 완료된 상태이므로 오류를 서버 로그에 남기며, 같은 원본 ID로 다시 적용하지 말고 캐시를 점검합니다.

실제 병합으로 동일 회원의 이력 행이 생긴 뒤에는 예전 스키마의 유일성 제약으로 바로 다운그레이드할 수 없습니다. 스키마를 되돌려야 할 때는 배포 전 백업으로 복구하거나 이력 행을 보존하는 복구 계획을 먼저 수립합니다. `--apply` 실행 중 예외로 발생하는 트랜잭션 롤백과 실행이 완료된 병합의 복원은 다릅니다.
