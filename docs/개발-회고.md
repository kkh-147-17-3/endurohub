# 엔듀로허브 개발 회고 — 문제와 해결 과정

> 이 문서는 프로젝트 개발 기간 동안의 대화 기록(2026-01-24 ~ 2026-06-14, 총 82개 세션)을
> 분석해 정리한 회고다. **무엇을 만들었나**가 아니라 **어떤 문제에 부딪혔고 어떻게 풀어나갔나**에 초점을 둔다.
>
> 자료 한계: 1·2기(Laravel 시절)는 세션 본문이 삭제되고 인덱스 메타데이터(요약 + 첫 질문 + 날짜)만
> 남아 있어, "무슨 문제였는지"는 확실하나 "해결 세부"는 요약 기반 추정이다. 3기(Django+SvelteKit)는
> 전체 대화 본문이 보존되어 있어 원인·해결까지 구체적이다. **2026-02-02 ~ 05-16 사이는 저장된 기록이 없다.**

## 한눈에 보는 진화 — 3단계

엔듀로허브는 두 번의 큰 아키텍처 전환을 거쳤다. "마라톤 크롤링 + 연간 캘린더"라는 핵심은 첫날부터 변하지 않았다.

| 단계 | 시기 | 스택 | 기록 상태 |
|---|---|---|---|
| **1기** Laravel + Blade | 2026-01-24 ~ 01-31 | Laravel · Filament · Blade · Tailwind | 메타데이터만 |
| **2기** Laravel + Inertia + Svelte | 2026-02-01 ~ 02-02 | + Inertia.js · Svelte 5(TS) | 메타데이터만 |
| **3기** Django + SvelteKit | 2026-05-16 ~ 06-14 | Django REST · SvelteKit SSR · daisyUI | 전체 본문 |

CLAUDE.md에 적힌 "Laravel → Django 마이그레이션"의 출발점이 1·2기다.

## 1기 — Laravel + Blade (1/24 ~ 1/31)

### 환경 셋업의 진통
- `plan.md` 기반 Laravel 프로젝트 셋업, **PHP 경로 설정** 문제 (39메시지로 가장 길었던 셋업 세션)

### 크롤링 파이프라인 (현재 시스템의 뿌리)
- "marathon.pe.kr 크롤링해서 정보를 받아오려고 해" → **Laravel 크롤러** 구축
- **시간별(hourly) 스케줄 + 이메일 리포트** 자동화
- "방금 크롤링했던 과정 skills.md로 정리해줘" → 크롤링 절차를 스킬 문서로 정리
  → **3기 `/import-races` 스킬의 원조**

### Filament 어드민
- **이미지 업로드 크기 제한 에러**
- race-card 이미지 표시 수정 + "최근 추가된 대회" 섹션
- "클릭하면 파일선택 떠서 불편 → 호버 방식으로" UX 개선

### 연간 대회 캘린더 UI (이미 이때부터 핵심 화면)
- "`${currentYear}년 대회보기` 만들어줘, marathon.pe.kr 느낌으로" → 연간 목록 페이지
- **월 sticky 고정 안 됨** 버그
- **뱃지 최소 너비** — "트레일러닝" 같은 긴 뱃지에서 레이아웃 깨짐
- 모바일 캘린더 full-width 패딩, 월 네비게이션 **활성 상태 표시 누락**
- `/ui-ux-pro-max`로 캘린더 디자인 개선 자문 / "더 컴팩트하게?" 논의

### SEO·OG (브랜딩 시작)
- "og:title에 엔듀로허브 나왔으면, 검색엔진에서 브랜드명이 안 잡힌다" → 메타태그 최적화

## 3기 — Django + SvelteKit (5/16 ~ 6/14)

전체 작업의 핵심 루프: **Claude Design 프로토타입(`v2/*.html`) 수신 → SvelteKit 구현 → 실제와 디자인 차이 발생 → 헤드리스 브라우저로 비교 → 수정**의 반복.

### 1. 디자인 ↔ 구현 불일치 (가장 빈번)
"디자인이랑 너무 다른데", "간격이 다 다르잖아"가 반복됨.

| 세부 문제 | 해결 |
|---|---|
| 구현이 시안과 어긋남 | **헤드리스 브라우저(Playwright)로 캡쳐 → 디자인과 나란히 비교**. 이후 "검토는 별도 에이전트로" 분리 |
| 디자인 번들이 오래됨(stale) | 매번 핸드오프 URL에서 번들 재다운로드(19~29MB tar.gz). canonical 소스 = `project/v2/*.html` |
| 핸드오프 URL 만료(404) | `/h/...`는 일회성 → 디자인 재export로 새 URL 발급 필요 확인 |
| 번들에 `_ds/` 토큰 폴더 누락 → 빈 화면 렌더 | 앱의 실제 `eh-tokens.css`/`eh-components.css`를 시안에 주입해 렌더 후 비교 |
| 구버전 소스 참고로 방향 어긋남(모바일 탭바) | DesignSync 구버전 JSX 대신 **v2 canonical HTML 기준**으로 재구현 |
| Pretendard 폰트 일부 미적용 | 원인은 `--font-mono`가 시스템 monospace(Windows Consolas)로 fallback → 토큰 한 줄(`--font-mono: var(--font-sans)`) 수정으로 전역 해결 |

### 2. 캘린더 지도 — 가장 긴 시행착오
- **라이브러리 선택**: leaflet/kakaomap 검토 → **SVG 카토그램** 채택. 카카오맵 비교 페이지는 만들었다가 결국 제거
- **행정구역 depth 불일치**("왜 어디는 구까지, 어디는 시까지만"): 세종이 단층제라 시·군·구 데이터 없음 → **읍·면·동 17개 추가 + 세종 폴리곤에 클립**
- **서울·경기 버블 겹침**: 서울이 경기 안 → `BUBBLE_NUDGE`로 분리
- **클러스터 핀 호버 UX**: 인접 핀 묶기 → 단일 컨테이너 카드 + **220ms grace 타이머**로 깜빡임 방지
- 성능(fan-in/out 랙), 경계면 거칠음(둥글게 시도 후 되돌림), 날씨 아이콘 추가

### 3. 목업 데이터 vs 실제 백엔드 데이터 간극
- **빈 우측 레일**: `popularPosts:0`, `sameRacePosts:0` → 큰 데드 스페이스 → **단일 컬럼(720px)으로 단순화**
- **마이페이지/온보딩**: Strava·PB·알림 매트릭스 등 백엔드 모델 없는 항목은 **가짜 데이터로 채우지 않고 의도적으로 제외**
- 커뮤니티/공지 분류·카운트도 실데이터 한계로 현 상태 유지

### 4. 로직·계산 버그
- **훈련플랜 "4주" 버그**: 디자인 데모값 `Math.max(4, …)` 바닥값 때문에 오늘 열리는 대회(D-0)도 무조건 4주로 계산 → 과거 날짜의 가짜 플랜. 바닥값 제거 + 목표 대회를 **30일 이상 남은 것만** 필터
- **캘린더 마감 뱃지 안 뜸**: 공유 스니펫에 `closed` 분기 누락 → `{:else}접수 마감` 추가
- **회원가입 unique constraint 충돌**: `nickname=''` 중복 → `null` 허용(Postgres는 NULL 다중 허용)

### 5. 자연어(LLM) 검색
- 로컬 LLM(LM Studio) → **Claude API로 전환**
- structured output 실패 시 프롬프트-온리 1회 재시도하는 **2단 폴백**
- 단발 파이프라인(질의 1건당 LLM 1회 + 결정론적 ORM 필터)
- 최종적으로 UX 정리 차원에서 **`/search` 라우트 제거**, 대회명 검색은 `/races`로 통합(코드는 주석 보존)

### 6. 데이터 임포트(대회 크롤링)
- "url은 ridy 사이트가 아니라 참고하는 다른 링크여야 해" → **`source_url`은 집계 사이트가 아닌 실제 주최처 링크** 규칙 확립
- 사이트별 헤드리스 보강 노하우 축적 → **`/import-races` 스킬로 재사용화**

### 7. 모바일 반응형
- 바텀시트 + 배경 스크롤 락, 모바일 탭바, 헤더 로고/아이콘 배치
- **히어로 배너 PC/모바일 잘림** → `<picture>`로 분기
- training-plan 7컬럼 그리드 → 단일 컬럼 리플로우

### 8. 분석(Analytics)
- GA/PostHog 전환 이벤트 누락 검토 → **5종 추가**(review_submit, post_create, search, login, sign_up)
- 서버 리다이렉트로 완료되는 로그인/가입은 1회용 쿠키(`eh_evt`) 브리지로 발화

### 9. 인프라·Git 잡음
- SvelteKit SSR이 Django 미기동 시 **ECONNREFUSED(500)**
- **포트 충돌**: 3000은 Windows 서비스 점유, stale `:3100`이 깨진 페이지 서빙
- Playwright `.playwright-mcp` 락으로 브라우저 미기동
- master↔v2 **머지 충돌 11개 파일을 v2(ours)로 해결**, CRLF 정규화, PR #1/#2 생성

## 통합 회고 — 반복된 패턴

전체 기록을 합치면 처음부터 끝까지 일관된 주제가 뚜렷하다.

1. **같은 화면(캘린더)을 계속 다시 만든다** — Blade 캘린더(1기) → Svelte 캘린더(2기) → SvelteKit 캘린더/지도(3기). 매번 *월 고정·뱃지·반응형·디자인 일치*라는 동일한 함정을 다시 만남.
2. **크롤링 → 데이터 적재**가 첫날(marathon.pe.kr)부터 핵심이었고, 그때마다 *"과정을 스킬로 정리"* 하는 습관이 `/import-races`로 결실.
3. **"구현이 기준과 다르다 → 대조 → 정밀 수정" 루프**가 1·2기의 Tailwind 비교에서 3기의 헤드리스 브라우저 자동 캡쳐 비교로 **방법론이 고도화**됨. 검증 전담 에이전트 분리까지 발전.
4. **환경/툴체인 잡음**(PHP 경로·Xdebug·devcontainer·포트 점유 → ECONNREFUSED·포트 충돌·Playwright 락)은 단계 불문 꾸준한 배경 소음.
5. **데모/목업 값의 함정** — 디자인 프로토타입의 샘플 데이터를 그대로 가져오면(빈 레일, 4주 플랜, mono 폰트) 실서비스에서 버그가 됨. "가짜 데이터로 채우지 않는다"는 원칙이 자리잡음.

요약하면 엔듀로허브는 **Laravel+Blade → Laravel+Inertia/Svelte → Django+SvelteKit** 두 번의 대전환을 거쳤고, 핵심 도메인(마라톤 크롤링 + 연간 캘린더)은 변하지 않은 채 프론트엔드 구현 방법론만 계속 정교해졌다.
